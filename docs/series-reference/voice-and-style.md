# 从旧作对白提炼的口语与人物指南

## 怎么“像同一个系列”

目标是玩家读到熟悉的称名、说话逻辑和喜剧节奏。不是逐字模仿旧译，也不是把每句写成段子。以下原译只作局部证据；分析和建议是本次编写的编辑规范。

### 把英文语用换成中文语用

英文里的 you know、I mean、like、literally、well 先判断是犹豫、补刀、改口还是强调。可转成“说真的”“不是，我是说……”或语序、停顿，不要求每次都留下相同词语。

- `Both Polly and Liam look to you expectantly. Now is your chance to save the night!`
  → 旧译：“波莉和李姆期盼地望向你。轮到你来救场了!”
  “救场”比“拯救这个夜晚”更符合这里的说话目的。保留前句铺垫与后句短促推进。
  证据：`level6:2888:758580`。
- `Literally.` → 旧译：“是真的融化了。”
  这类补刀会承接前句的比喻；不能脱离上下文统一成“字面上”。这里的“融化”仅适用于该上下文。
  证据：`level6:2888:37984356`。

### 让笑点落在句末，让反差留在同一句里

- Miranda 的介绍 `a sweet mermaid princess who was as cute as she was genocidal`
  → “甜心人鱼公主,可爱到灭绝人寰。”
  借中文措辞把甜美与残酷压进一句，这是可借鉴的浓缩方式。新台词仍须保留对剧情有用的字面信息，不能为了四字词省略关键内容。
  证据：`level2:976:8968`。
- `The Prank Masterz strike again!` → “恶作剧大师再度出手!”
  保留熟悉的团队口号节奏；同类回扣保持用词，别每次创造新称号。
  证据：`level6:2888:15081564`。

### 粗口与亲昵各有力度

- `You can bet I fuckin' am!` → “这他妈还用你说!”（`level6:2888:38351108`）
  用自然回嘴承接上句，粗口属于已有语气，不是通用装饰。
- `What are you talking, boo?!` → “你到底在说什么啊,宝贝?!”（`level6:2888:38548896`）
  boo 在此是亲昵称呼，不等于所有场合都应译为“宝贝”，更不应总按鬼叫“呜”处理。

## 人物差异

以下是取样后的编辑方向，不是固定口头禅表。对白中的角色槽位如 Duo_1、Trio_2 要结合完整事件判断；证据文件的 preceding 是邻近字符串，不能将其最后一项直接当成说话人。

| 人物 | 可沿用的说话逻辑 | 避免的偏差 |
|---|---|---|
| 波莉 | 直来直去地邀人玩、调情、起哄；失望时迅速抱怨或反击；短促且随性 | 每句话都尖叫；平白加黄段子；统一用“宝”“绝了” |
| 斯科特 | 热情、把朋友和团队当回事；认真地按字面理解荒诞建议，让天真制造笑点 | 写成处处挖苦人的老油条；用弱智腔代替真诚 |
| 李姆 | 在意品味、独特性与排外资格；可用稍讲究的词之后突然露出小心眼 | 全文文言腔；把 hipster 固定理解成 hippie；丢掉自命不凡的反差 |
| 薇拉 | 控制局面、算成本、冷淡反问；挖苦常用逻辑本身完成 | 为了刻薄到处加脏话；甜妹语气；改回薇娜或维拉 |
| 德魔 | 急躁、挑衅、逞强、行动优先；原文爆发时中文也要有力度 | 无论脆弱、认真还是愤怒都使用同一种咆哮 |
| 米兰达 | 甜美、理所当然的王室特权；残酷制度被当成日常常识 | 主动替她批判特权；为了可爱抹去黑色笑点 |
| 计算斯基 | 精确措辞、计算与程序术语、礼貌求知；机械形式与真诚情感并存 | 所有话都写成系统报错；把已有情感译没了 |
| 兹伊 | 角色介绍强调从神祇到粉丝女孩的反差；宅圈表达随当前英文落实 | 把 shipping 机械译为“送货”；随意塞入原文没有的中文圈内梗 |
| 四位可选主角 | 已核实的是默认姓名；按当前作品的实际对白确定口吻 | 从可选人物立绘或默认名字推断固定人格；改掉玩家命名变量 |
| 其他 NPC | 按当前事件的身份、关系、叙事功能选语域；姓名查表 | 只有一个称名证据就编出完整性格、口癖或剧情史 |
| 旁白 | 用“你”推进场景；认真描述荒唐行为，临尾吐槽或自嘲；资源结算要清楚 | 把旁白改成攻略说明；提前解释后面的包袱 |

### 人物表达的实际参照

- 李姆相关酒吧事件：`My modus operandi is to be the instigator of exclusivity, not the victim of it.`
  旧译：“排外明明是我的专长,现在却成了这家伙的武器。”
  继承“本来该我排斥别人”的自负；当前作品若需要保留刻意正式的 modus operandi，可以稍带书面措辞，不必总压成普通抱怨。
  `level6:2888:752948`。
- 薇拉相关酒吧事件：`I'm into this crazy new thing called "paying for my own drinks." Maybe you've heard of it?`
  旧译：“我最近很喜欢\"自己买单喝酒\"这种新鲜事情。你应该听说过吧?”
  保留把普通行为包装成新潮事物的冷讽；不必添加“蠢货”来证明她刻薄。
  `level6:2888:1600196`。
- 计算斯基：`Should I merely be using the physics of the existing world? Or should I innovate?`
  旧译：“我应该完全运用真实世界的物理规则,还是进行创新?”
  稍正式但通顺，保留认真询问的逻辑。
  `level6:2888:32215772`。
- `...SEARCHING VALID EXCUSE...` → “......正在搜索有效借口......”
  机器状态形式本身就是笑点，不能平抹成“让我想想怎么拒绝”。
  `level6:2888:38247932`。

## 旧译里不应继承的东西

1. **漏掉成对双关。** 斯科特相关 cosplay 对话的 `half-ass` / `full ass` 被旧译处理为“随便对付”/“认真对待一切”，保留了意思却丢掉字面“屁股”的误解。处理新台词时先识别两端，不应把这条旧译当成完整的双关范本。`level6:2888:942724`。
2. **抹去残酷反差。** 米兰达把动物 `deeply pained expression` 看成喜爱的证据，旧译仅剩“水汪汪的小眼睛……非常喜欢”。新译应保留“痛苦”，否则黑色笑话消失。`level6:2888:1102928`。
3. **脱离语境的多义词。** `Best at Shipping` 在兹伊的角色评语中被译为“最擅长送货奖”；这里须检查配对／嗑 CP 的语境。`flyer` 在后续事件须确认是传单还是其他含义，不能看到旧译“航班”就沿用。`level6:2888:38691944`、`level6:2888:2530868`。
4. **旧作内部名称不统一。** 正文、片尾、画廊可能采用不同叫法；选定项目规范后不随例句摇摆。尤其 Vera 按用户指示用薇拉。
5. **版本与格式习惯。** 旧译中的半角标点、六个句点、偶见繁体字不能自动变成新项目的规范。保持目标项目的简体中文排版与引擎要求；标签、变量另行原样保留。

## 每个事件的审校顺序

读完铺垫、分支和结果 → 确认人物和称名 → 把含义与笑点讲清楚 → 调整中文口语节奏 → 检查人物差异 → 检查变量与字段。系列连贯性不能覆盖当前作品的事实，也不能掩盖旧译自身的问题。
