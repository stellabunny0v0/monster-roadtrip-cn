# v0.3.4 属性结算与右上角显示修复

日期：2026-10-30。用户实测反馈：所有选项后的 N2 标记未被换算，右上角属性数值不变，名称仍为英文。

## 根因与影响

游戏不是只靠 TSV 控制列结算资源。`Game.MainGameEventManager.ProcessStatPatterns` 会从正文中用 `RegexUtils.GetRegexStatAny` 读取正负号、N 因子、数字和英文 StatType 名称，加入待结算列表。`ConvertTextTags` 依次应用先前结算、位置／角色修正、属性结算、恶作剧币结算和其他变量。`RoadtripEventManager` 还会在数值事件第三个选项预计算时扫描原始正文。

v0.3.3 译文中的中文属性名不符合这个协议；即便英文属性名保留，紧接中文也可能因 .NET 的 Unicode 单词边界而匹配失败。之前仅保护 N 数字、STA_* 和 TSV 非正文列不足以保证结算。对实际安装文件回归：1,062 条原文属性行中 1,059 条不等价，原有 1,342 个有效标记仅 4 个仍可识别；27 处 +XX PRANK DOLLARZ 奖励也失去识别。

右上角来自 `Game.StatWidget.Initialize` 的 `type.ToString()`，没有经过词表，因此保留英文。不能为修复这个显示而翻译参与解析的 STA_* 数据值。

## 修复边界

- `tools/stat_contracts.py` 在构建事件正文时恢复六项英文属性结算名和 +XX PRANK DOLLARZ；不改正负号、N、数字、数量或出现顺序。中文紧接处补充 ASCII 边界。译文 CSV 继续可读，实际载入文本遵循原版协议。
- 译文校验会先试编译结算标记，构建后校验使用原游戏的正则／枚举语义再次与源文件对照。未知的笑话奖励（例如 +1 新奶奶）不会变成真实属性奖励。
- 动词 sidecar 的预期文本和展开结果均从同一编译后正文生成，避免旧期望值失配或重新引入中文结算标记。
- 仅在 MainGameEventManager.ConvertTextTags 原方法返回之后本地化已完成的彩色数值反馈。原游戏负责周数／难度倍率、乘客效果、排队与实际加减，插件不复制或绕过这些算法。
- 右上角 StatWidget 两个 Initialize 重载均处理：前缀设置中文字体，使随后克隆的辅助标签同样支持中文；后缀把六个固定名称转成热度、魔力、头脑、金钱、灵魂、体力。数值标签和底层 StatType 不变。
- 两条源译文回改见 stat-cue-fixes-001.csv：L4951 恢复 HYPE-itis 里的完整负数标记；L24509 按原文保留先体力增益、后头脑损失的顺序。首次审校覆盖量不增加。

## 已执行验证

- 22 项 Python 测试通过，涵盖符号、N 因子、数字、属性、顺序、缺失／多余奖励、中文边界、控制标签以及动词 sidecar 联动。
- C# 回归使用与游戏完全相同的 .NET 正则和枚举读取方式：全量 1,342 个属性标记、1,062 行，以及 27 处恶作剧币奖励均与英文原版一致；所有非正文控制列一致。
- C# 显示检查覆盖彩色正负反馈、六项名称、奖励、未结算 N 标记和自定义属性名；未结算标记不会过早转成中文。
- 原 59 条动词适配在 11 个事件文件的实际 C# 消费函数验证仍通过。
- 翻译表与构建事件协议校验通过；插件 Release 编译 0 警告、0 错误。
